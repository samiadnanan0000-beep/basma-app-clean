# تطبيق بَصْمَة (Basma) — منصة إدارة وتتبع أعمال الدعاية والطباعة

تطبيق أندرويد نيتف (Native Android) متكامل مبني باستخدام Jetpack Compose و Material 3 بهوية Samsung One UI، يربط عملاء استوديو الدعاية والإعلان بإدارة ومصممي الاستوديو عبر نظام أدوار محكم (One App - Two Roles) مع عزل أمني تام للبيانات، مركز تنبيهات فوري، حاسبة إنتاج اللوحات والكلادنج، وقفل أمني بالبصمة.

## 1. نظرة عامة والمفهوم الأساسي (Overview & Core Concept)

- **ما يقدمه التطبيق**: منصة موحدة وشاملة للطباعة والدعاية والإعلان، تتيح للعملاء استعراض سابقة الأعمال، طلب تصاميم ولوحات مخصصة مع إرفاق الشعارات ومقاسات الواجهات، وتتبع مسار العمل ومراجعة "البروفات" والتسعير لحظة بلحظة. وفي المقابل، تمنح الإدارة والمصممين لوحة تحكم متقدمة لإدارة الطلبات، تسعير الأعمال، إدارة الخامات والمطابع الوسيطة، ومعالجة الشكاوى والاقتراحات.
- **الفئات المستهدفة**:
  1. **العملاء وأصحاب الأنشطة التجارية**: طلب الهويات البصرية، لوحات المحلات والكلادنج، ومتابعة بروفات الطباعة.
  2. **المدير العام والمصممون الأساسيون**: مراجعة وإرسال التسعيرات والبروفات، إدارة تكاليف الإنتاج، وتوزيع الصلاحيات.
- **القيمة المضافة**: التخلص من فوضى الرسائل المشتتة عبر واتساب، توفير حاسبة دقيقة لتكلفة لوحات الكلادنج، وسرعة اعتماد البروفات والتواصل عبر إشعارات فورية وتنبيهات حية.

## 2. تجربة المستخدم والتصميم البصري (Samsung One UI Standard)

### المسارات التفاعلية الأساسية (Key User Flows)

1. **مسار القفل الأمني والمصادقة (Biometric & Auth Flow)**:
   - فحص الحماية البيومترية فور فتح التطبيق (بصمة الإصبع / التعرف على الوجه) مع إمكانية استخدام رمز PIN كخيار بديل.
   - تسجيل الدخول الموثوق برقم الهاتف والبريد الإلكتروني وحل الرتبة تلقائياً (`super_admin` أو `designer` أو `client`).
2. **مسار العميل (Client Journey)**:
   - **الرئيسية**: شريط عروض تفاعلي متحرك (`HorizontalPager`)، شبكة سابقة الأعمال (Portfolio)، وزر بارز لطلب عمل جديد.
   - **نموذج طلب عمل جديد**: اختيار الفئة، اختيار الخامة ديناميكياً من قاعدة البيانات، إدخال الأبعاد (العرض × الارتفاع)، إدخال نصوص التصميم، وإرفاق الشعار وصورة الموقع/الواجهة.
   - **خط تتبع الطلبات**: تتبع الطلب من مرحلة "بانتظار التسعير" 🟡 -> "تم التسعير" 🔵 (مع خيارات القبول/الرفض) -> "قيد التنفيذ" 🟢 -> "جاهز للتسليم" 🏁 مع فحص البروفات واعتمادها.
3. **مسار المصمم والإدارة (Designer Hub)**:
   - صندوق الطلبات الواردة مع إمكانية نسخ نصوص العميل بضغطة زر وتنزيل المرفقات.
   - نافذة تسعير الطلب وتحديد موعد التسليم وإرسال البروفات المائية للعميل.
   - حاسبة إنتاج اللوحات والكلادنج (حساب المساحة بالمتر المربع، شاسيه الحديد، محولات الليد والزنكور).
   - إدارة الخامات والأسعار (CRUD)، إدارة عروض الاستوديو، وسجل المطابع الشريكة.
   - صندوق معالجة الشكاوى والاقتراحات والرد المباشر عليها.
4. **التبديل إلى وضع العميل (Role Preview)**:
   - زر علوي للمصمم والمدير للتبديل الفوري لمعاينة رحلة العميل كما يراها بالضبط، مع زر عائم ثابت للعودة الفورية للوحة المصمم.

### الهوية البصرية ونظام التصميم

- **نمط Samsung One UI**: بطاقات منحنية انسيابية بتدوير زوايا متناسق (Squircle 20dp - 26dp)، عناصر تحكم مريحة وسهلة الوصول بيد واحدة في الجزء السفلي من الشاشة.
- **نظام الألوان المتوافق (Dual Theme)**:
  - **الوضع الفاتح**: خلفية نقية `#F3F4F8`، مساحات مرتفعة `#FFFFFF`، نصوص كحلية `#121316`، ولون مميز One UI Blue `#0381FE`.
  - **الوضع الداكن**: خلفية داكنة راقية `#0B0C0E`، مساحات مرتفعة `#17181C`، نصوص مضيئة `#F5F6F8`، ولمسات زرقاء `#3B82F6`.
- **الطباعة ودعم RTL**: دعم كامل للغة العربية ومحاذاة الشاشات وتدفق القوائم من اليمين إلى اليسار (RTL-First).

## 3. القرارات التقنية والمعمارية (Key Architectural Decisions)

- **بنية "تطبيق واحد برتبتين" (One App - Two Roles)**: بدلاً من بناء تطبيقين منفصلين، يتم توفير بيئة متكاملة تكتشف صلاحيات المستخدم من وثيقة `users/{uid}`، وتفصل بين تدفقات العميل والمصمم مع ضمان أمان كامل عبر قواعد أمان Firestore.
- **العزل الأمني الصارم لبيانات العملاء (Strict Multi-Tenant Isolation)**:
  - يستعلم العميل فقط عن الطلبات والشكاوى الخاصة بمعرفه (`clientId == auth.uid`).
  - المصممون والمدير العام يمتلكون صلاحية الوصول لكافة الطلبات الواردة لغرض التسعير والتنفيذ.
- **التحديث اللحظي عبر مراقبي التدفقات (Firestore Snapshots & StateFlow)**:
  - استخدام `snapshots()` في مستودعات البيانات لإطلاق تدفقات فورية تعكس أي تعديل في الأسعار أو البروفات أو الإشعارات دون الحاجة لإعادة تحميل الشاشة يدوياً.
- **قفل التطبيق البيومتري (Biometric Prompt + Encrypted SharedPreferences)**:
  - استخدام مكتبة `androidx.biometric:biometric-ktx` للتحقق السريع من بصمة الإصبع أو الوجه مع حفظ حالة التفعيل والرمز الاحتياطي في DataStore بأمان.

## 4. المخطط المعماري واستراتيجية البيانات (Technical Architecture)

### مخطط تدفق النظام والمكونات (System Architecture Diagram)

```
┌────────────────────────────────────────────────────────────────────────┐
│                          تطبيق بَصْمَة (Basma)                          │

├──────────────────────────────────┬─────────────────────────────────────┤

│  - شريط العروض وسابقة الأعمال    │  - صندوق الطلبات والتسعير الفوري   │
│  - نموذج طلب تصميم وطباعة جديد   │  - رفع البروفات وحاسبة الكلادنج     │
│  - متابعة حالات الطلبات واعتمادها│  - إدارة الخامات والمطابع الشريكة   │

├──────────────────────────────────┴─────────────────────────────────────┤
│ 2. طبقة العرض والتحكم (MVVM ViewModels):                               │
│    AuthViewModel, OrderViewModel, MaterialsViewModel,                   │
│    NotificationsViewModel, ComplaintsViewModel, CalculatorViewModel    │
├────────────────────────────────────────────────────────────────────────┤
│ 3. طبقة المستودعات والبيانات (Repository Pattern):                     │
│    AuthRepository, OrderRepository, MaterialRepository,                │
│    NotificationRepository, ComplaintRepository                         │
├────────────────────────────────────────────────────────────────────────┤
│ 4. طبقة التخزين السحابي (Cloud Firestore & Firebase Auth):              │
│    - /users/{uid} (الأدوار وبيانات الاتصال)                            │
│    - /orders/{orderId} (الطلبات، الأبعاد، الأسعار، البروفات)            │
│    - /materials/{matId} (الخامات وتكاليف المتر والوحدات)               │
│    - /notifications/{notifId} (إشعارات العروض، الطلبات، والردود)       │
│    - /complaints/{complaintId} (التذاكر، الشكاوى، وردود المصمم)        │
│    - /offers/{offerId} (عروض بصمة الحصرية وسابقة الأعمال)              │
└────────────────────────────────────────────────────────────────────────┘
```

### بنية مجموعات Firestore ونموذج البيانات (Data Entities)

1. **مجموعة المستخدمين (`users/{uid}`)**:
   - `uid`, `name`, `email`, `phone`, `role` ("super_admin" | "designer" | "client"), `createdAt`.
2. **مجموعة الطلبات (`orders/{orderId}`)**:
   - `id`, `clientId`, `clientName`, `clientPhone`, `category`, `materialId`, `materialName`, `width`, `height`, `brandText`, `contactDetails`, `notes`, `logoUrl`, `sitePhotoUrl`, `status` ("pending" | "quoted" | "in_production" | "completed"), `price`, `currency`, `turnaroundTime`, `proofUrl`, `proofApproved`, `createdAt`, `updatedAt`.
3. **مجموعة الخامات (`materials/{materialId}`)**:
   - `id`, `name`, `unitType` ("متر مربع" | "لوح" | "قطعة"), `pricePerUnit`, `currency`, `inStock`, `updatedAt`.
4. **مجموعة الإشعارات (`notifications/{notificationId}`)**:
   - `id`, `title`, `message`, `type` ("offer" | "order" | "general" | "complaint"), `targetId` ("all" أو `clientUid`), `isRead`, `relatedId`, `createdAt`.
5. **مجموعة الشكاوى والاقتراحات (`complaints/{complaintId}`)**:
   - `id`, `clientId`, `clientName`, `clientPhone`, `type` ("complaint" | "suggestion" | "inquiry"), `subject`, `message`, `orderId`, `status` ("pending" | "resolved"), `replyMessage`, `createdAt`, `resolvedAt`.
6. **مجموعة العروض وسابقة الأعمال (`offers/{offerId}`)**:
   - `id`, `title`, `description`, `imageUrl`, `discountBadge`, `category`, `isActive`, `createdAt`.

## 5. خطة التنفيذ الممنهجة (Phased Execution Plan)

1. **الخطوة 1: تهيئة الهوية والاعتماديات والموارد**:
   - تحديث `metadata.json` وتعيين اسم التطبيق `بَصْمَة` ووصفه بالكامل.
   - تحديث `app/build.gradle.kts` وتفعيل الاعتماديات المطلوبة: Firestore, Auth, Credential Manager, Coil, Biometrics, DataStore, Navigation Compose.
   - تهيئة الموارد النصية (`strings.xml`) والألوان والسمات الخاصة بـ One UI.
2. **الخطوة 2: طبقة الأمان السحابي وقواعد Firestore**:
   - صياغة مخطط `firebase-blueprint.json` الشامل.
   - كتابة ونشر قواعد الأمان المحكمة `firestore.rules` التي تعزل بيانات العملاء وتمنح المصممين والمدير العام صلاحيات الإدارة والتسعير.
3. **الخطوة 3: طبقة المستودعات والبيانات (Repository & Seeders)**:
   - إنشاء نماذج البيانات (Data Models) مع قيم افتراضية متوافقة مع Firestore.
   - إنشاء مستودعات العمليات (`AuthRepository`, `OrderRepository`, `MaterialRepository`, `NotificationRepository`, `ComplaintRepository`).
   - تضمين بذور البيانات التلقائية للمواد وسابقة الأعمال لضمان جاهزية العرض التجريبي فور الإقلاع.
4. **الخطوة 4: واجهات العميل وطلب الأعمال**:
   - شاشة القفل البيومتري وبطاقة تسجيل الدخول مع التحقق من الهوية.
   - شاشة الرئيسية مع شريط العروض وسابقة الأعمال.
   - نموذج طلب العمل مع لاقط الصور المدمج، اختيار الأبعاد والخامات، واحتساب المساحة التقديرية.
   - شاشة تتبع الطلبات مع مسار المراحل واعتماد البروفات.
   - مركز الإشعارات الفوري ونافذة تقديم وتتبع الشكاوى.
5. **الخطوة 5: لوحة تحكم المصمم والإدارة (Designer Hub)**:
   - صندوق الوارد وتسعير الطلبات مع رفع البروفات.
   - حاسبة إنتاج اللوحات والكلادنج وشاسيهات الحديد ومحولات الليد.
   - إدارة الخامات، المطابع الوسيطة، وصندوق الرد على الشكاوى.
   - التبديل السلس لوضع العميل والزر العائم للعودة.
6. **الخطوة 6: الفحص والبناء النهائي**:
   - التحقق من تجميع التطبيق بنجاح عبر `compile_applet`.
